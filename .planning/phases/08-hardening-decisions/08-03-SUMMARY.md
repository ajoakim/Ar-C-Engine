# Phase 8 Plan 03: Software-adapter image-diff harness Summary

Software-adapter offscreen constructor, a golden-based image-diff suite (4 scenes plus negative controls) with Windows WARP goldens, and a separate CI job requiring the adapter on Linux and Windows.

## Commits

- 259e823 fix: clippy `chunks_exact_to_as_chunks` lint in the harness (found by workspace clippy after the first commit).

## Calibration
WARP ("Microsoft Basic Render Driver (Dx12)") was available locally. Goldens were generated twice with `ARC_UPDATE_GOLDENS=1`; the two generations were byte-identical (`cmp`). Two further verify runs (with `ARC_REQUIRE_GOLDENS=1 ARC_REQUIRE_ADAPTER=1`) reported max channel delta 0 and 0 differing pixels on all four scenes. Constants kept at the plan's values: `CHANNEL_TOLERANCE = 2`, `MAX_BAD_FRACTION = 0.005` (0.5%). They are headroom for driver updates, not observed noise. Linux/lavapipe and macOS tolerances are not calibrated (no local access).

## Negative controls
In-memory: an 8x8 block off by 40 fails; one off pixel passes (budget is real); delta 3 on every pixel fails. GPU: a one-pixel geometry shift fails against the base render, and a repeat render is within tolerance. Dimension mismatch returns Err with sizes.

## Deviations from Plan
None of substance. The plan said "unit test over all eight combinations": done in `golden_action_all_combinations`. CI uses matrix `include` values for `WGPU_BACKEND` and `require_adapter` (empty string on macOS means the flag is not "1").
