<rules>
Location of a workspace package = path of its manifest directory relative to `workspace_root`, split with `Path::components()` (never string-prefix with "/"; Windows CI uses backslashes - Pitfall 6):
- first component `crates` -> Core
- first component `extensions` -> Extension { family: second component } (e.g. "conventional-3d", "planetary")
- anything else -> Tooling
A dependency is "workspace-internal" when `dep.name` equals the name of a workspace package of the same metadata. ALL dependency kinds (normal, dev, build) are checked (Pitfall 7).

| Rule enum variant | id() string | Fires when |
|---|---|---|
| CoreDependsOnExtension | `core-depends-on-extension` | Core package depends on a workspace package located in Extension |
| WgpuOutsideAllowedCrate | `wgpu-outside-allowed-crate` | any package not in WGPU_ALLOWED declares a dependency whose `name == "wgpu"` |
| WinitOutsideAllowedCrate | `winit-outside-allowed-crate` | any package not in WINIT_ALLOWED declares a dependency whose `name == "winit"` |
| ExtensionCrossDependency | `extension-cross-dependency` | Extension{f1} package depends on a workspace Extension{f2} package with f1 != f2 |
| TierViolation | `tier-violation` | both packages are in LAYERS and tier(dep) >= tier(pkg); EXCEPT when both are Extension with the same family (same-family extension crates may depend on each other) |
| UnlistedCrate | `unlisted-crate` | a Core or Extension package is not in LAYERS (Tooling packages are exempt) |
</rules>
</context>
