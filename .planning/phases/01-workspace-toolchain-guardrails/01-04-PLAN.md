```toml
# cargo-deny configuration. See docs/architecture/adr/0003-dependency-enforcement.md.
[graph]
all-features = true
targets = ["x86_64-unknown-linux-gnu", "x86_64-pc-windows-msvc"]

[advisories]
# RustSec advisory DB (network). Defaults deny vulnerabilities and unmaintained crates per installed version.
yanked = "deny"

[licenses]
allow = [
    "MIT",
    "Apache-2.0",
    "Apache-2.0 WITH LLVM-exception",
    "BSD-2-Clause",
    "BSD-3-Clause",
    "ISC",
    "Unicode-3.0",
    "Zlib",
]
confidence-threshold = 0.93

[licenses.private]
# Workspace crates are publish = false; their license (MIT OR Apache-2.0) is still declared.
ignore = true

[bans]
multiple-versions = "warn"   # wgpu/winit stacks duplicate often; revisit after Phase 3
wildcards = "deny"
allow-wildcard-paths = true  # workspace path deps of publish = false crates
deny = [
    { crate = "wgpu", wrappers = ["engine-render-wgpu"], reason = "GPU API confined to the backend crate (WS-03, ADR-0002)" },
    { crate = "winit", wrappers = ["engine-platform"], reason = "Windowing confined to the platform crate (WS-03, ADR-0002)" },
]

[sources]
unknown-registry = "deny"
unknown-git = "deny"
allow-registry = ["https://github.com/rust-lang/crates.io-index"]
```
Do NOT add an `allow = [...]` list under [bans] (it would deny every unlisted crate). If `cargo deny check licenses` rejects a license used by cargo_metadata's dependency tree that is OSI-approved and permissive, add that SPDX id to `allow` with a comment naming the crate; never add copyleft licenses (GPL/LGPL/AGPL/MPL) without stopping and reporting.

Write `.github/workflows/ci.yml` with exactly this structure (values are decisions, not suggestions):
```yaml
name: CI

on:
  push:
    branches: [main, master]
  pull_request:

permissions:
  contents: read

concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

env:
  CARGO_TERM_COLOR: always
  RUSTFLAGS: "-D warnings"

defaults:
  run:
    shell: bash   # required so `!` negation works on windows-latest (default shell there is pwsh)

jobs:
  build:
    name: build (${{ matrix.os }})
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, windows-latest]
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v4
      - name: Install pinned toolchain from rust-toolchain.toml
        run: rustup toolchain install
      - name: Assert pinned toolchain is active
        run: rustc --version | grep -F "1.99.0"
      - uses: Swatinem/rust-cache@v2
      - name: Format
        run: cargo fmt --all -- --check
      - name: Clippy
        run: cargo clippy --workspace --all-targets --locked -- -D warnings
      - name: Build
        run: cargo build --workspace --locked
      - name: Test
        run: cargo test --workspace --locked
      - name: Dependency direction (must pass)
        run: cargo run --locked -p xtask -- check-deps
      - name: Negative - core depends on extension (must fail)
        run: "! cargo run --locked -p xtask -- check-deps --manifest-path xtask/fixtures/core-depends-on-ext/Cargo.toml"
      - name: Negative - wgpu/winit misplaced (must fail)
        run: "! cargo run --locked -p xtask -- check-deps --manifest-path xtask/fixtures/wgpu-winit-misplaced/Cargo.toml"

  deny:
    name: cargo-deny
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Install pinned toolchain from rust-toolchain.toml
        run: rustup toolchain install
      - uses: taiki-e/install-action@v2
        with:
          tool: cargo-deny
      - name: cargo deny (bans, licenses, sources, advisories)
        run: cargo deny check bans licenses sources advisories
      - name: Negative - cargo-deny rejects misplaced wgpu (must fail)
        run: "! cargo deny --manifest-path xtask/fixtures/wgpu-winit-misplaced/Cargo.toml check --config deny.toml bans"
```
Notes: `cargo run -p xtask` is used instead of the `cargo xtask` alias so `--locked` applies. Keep third-party actions pinned to major tags (`@v4`, `@v2`); `permissions: contents: read` is least privilege. The `!` negation lines are quoted strings so YAML does not treat `!` as a tag.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runners -> repo | Third-party actions execute with the workflow token |
| crates.io / RustSec DB -> CI | Dependencies and advisory data fetched over the network |
| cargo install -> developer machine | cargo-deny compiled from crates.io into ~/.cargo/bin |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-12 | Elevation of Privilege | CI workflow token | mitigate | Top-level `permissions: contents: read`; no secrets used; `pull_request` (not `pull_request_target`) trigger |
| T-01-13 | Tampering | Third-party actions (checkout, rust-cache, install-action) | mitigate | Pinned to major tags `@v4`/`@v2`, never `@main`/`@master` (acceptance grep); SHA pinning can be adopted later |
| T-01-14 | Tampering | Vulnerable/malicious crates | mitigate | `cargo deny check advisories sources` in CI, `unknown-registry/unknown-git = "deny"`, `--locked` on all cargo commands with committed Cargo.lock |
| T-01-15 | Tampering | cargo-deny local install | mitigate | `cargo install cargo-deny --locked` uses the crate's published lockfile; user-level only |
| T-01-16 | Repudiation / license risk | Copyleft dependency slipping in | mitigate | Permissive-only `[licenses] allow` list; acceptance grep forbids GPL/MPL entries |
| T-01-17 | Denial of Service | CI resource use | accept | `concurrency` cancels superseded runs; low-value target |
</threat_model>
