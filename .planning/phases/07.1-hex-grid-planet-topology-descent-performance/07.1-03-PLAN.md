- `uploader.rs`: `HeldPatch` gains `pub range: HeightRange` from `mesh.height_min/height_max`.
- `system.rs`:
  - `pub const DRAW_MARGIN: usize = 24;` In `new`: reject `cfg.lod.max_leaves < 6` and `cfg.lod.max_leaves + DRAW_MARGIN > MAX_DRAWS_PER_FRAME` (`SdkError::App("lod.max_leaves must be in 6..=1000")`). Since effective-cut leaves are a coarsening of the wanted split (each split adds 3 leaves), drawn leaves <= wanted leaves <= max_leaves <= 1000.
  - `prepare`: `let held = &self.held; select(&self.model, &self.cfg.lod, view, &self.prev_split, &|id| held.get(&id).map(|h| h.range))`. Keep `self.last_view = Some(*view)` for draw culling.
  - `gpu_frame`: for each effective leaf with a held mesh: compute `cell_bound(radius, &patch_footprint(leaf), h.range)` and skip (count `culled_draws`) if `!frustum_visible(view, &bound)` or `!horizon_visible(...)` using the last view; otherwise push the RenderItem. Before pushing, if `scene.items.len() >= MAX_DRAWS_PER_FRAME` return `Err(SdkError::App(format!("draw budget exceeded: {} items", ..)))` (unreachable by the invariant; replaces the silent `overflow += 1; continue`). Remove the `draw_overflow` field from `TerrainReport`; add `pub pending_requests: usize` (= `self.requested.len()` after prepare), `pub draw_items: usize`, `pub culled_draws: u32`. `drawn()` keeps returning the full effective-cut leaves (the partition), so existing partition/balance tests keep their meaning.
- `camera.rs`: `pub fn frustum_planes(&self, aspect: f64) -> [[f64; 4]; 6]` in world space f64 from `position()`, `orientation()`, `TAN_HALF_FOV_Y`, `aspect` (clamped to [0.1, 10]) and `near_plane(altitude)` passed as `near: f64` argument: signature `frustum_planes(&self, aspect: f64, near: f64)`. Planes: near (normal = forward, through position + forward*near), left/right/top/bottom through the eye with inward normals from the camera basis (`orientation * X/Y`, forward = `orientation * -Z`), far plane = a disabled plane `[0,0,0,1]` (always inside) because the projection is infinite reverse-Z. Normalise each plane. Plain f64 trig is not used: the side normals come from `normalize(forward*tan_half + right)` style combinations (sqrt only).
- Tests: in `tests/terrain_stream.rs` add `config_rejects_draw_budget_overflow`, `resident_ranges_reduce_node_visits`, `draw_items_plus_culled_equals_drawn`; update any `draw_overflow` references. In `tests/camera.rs` add `frustum_planes_contain_view_axis`.
- planetary-app `telemetry.rs`/`lib.rs`: drop the `draw_overflow` column; add `pending_requests`, `draw_items`, `culled_draws` (the select columns were added in 07.1-02).
