<objective>
Define and compute the geomorph target on the planetary side, feasibly and provably continuous: the child's vertex moves to the surface the PARENT mesh actually draws at that direction. No octave-cut alternative (a height function with fewer octaves does not equal the parent mesh, which is piecewise linear between parent samples, so it would leave a pop of about the whole geometric error; it is not used).

Purpose: plans 23 (payload and GPU upload) and 24 (driving the factor) need a correct target; get it right and proven before any rendering depends on it.
Output: morph module, cube and hex locators, `CellMesh.morph`, seam/oracle tests. Payload stays v3 until plan 23 (the decoder fills an identity morph so the tree compiles).

Costs recorded, not asserted: worker mesh time rises because the parent lattice samples under the child footprint are evaluated (cube: about (n/2+1)^2 extra `terrain.sample` calls per cell, about +25%; hex: about the same share of the six sector grids). Record before/after mesh build time (printed micro-timing, release) in the SUMMARY.
</objective>

topology/mod.rs: `CellMesh { raw, vertex_class: u8, origin: DVec3, vertices: Vec<VertexPosNormalUv>, bound_radius: f32, skirt_depth: f64, height_min, height_max }` (literals at cell_payload.rs:176, hex/mesh.rs:259, topology/cube.rs:148). `Topology::build_mesh(&self, c, terrain, model, debug_cells, cancelled) -> Option<CellMesh>`; `primary_parent(c)` = lowest raw id parent; `parents(c, out)` ascending raw (0 for roots, 1 cube, up to 2 hex).
Cube (mesh.rs / mapping.rs): grid `(n+1)^2` vertices, `vertex_dir(id, n, i, j)` = `lattice_dir(face, gu, gv, g)` with `gu = id.x*n + i`, `g = n*2^level`, equal-angle map (exact-op); `n` is a power of two in 2..=64 so always even; position of grid vertex = `terrain.surface_point(dir)` (= `dir * (radius + height)`); grid triangles per quad: `(v00,v10,v11)` then `(v00,v11,v01)` (grid_indices); skirts: `4*(n+1)` vertices after the grid in `Edge::ALL` order, hung by `skirt_depth` along `-dir`. A child at quadrant `(ox, oy)` has parent lattice coordinate `(ox*n + i)/2` for index `i`: integer when `ox*n + i` is even (the child vertex IS a parent vertex), a half-step otherwise. uv_of(terrain, sample) = [height normalised by (max_relief - sea_level), mask].
Hex (hex/mesh.rs, hex/mapping.rs): vertex layout = sectors `k` (6, or 5 for a pentagon) each a triangular grid rows `s=0..=n`, `t=0..=n-s` (`grid_index(n,k,s,t)`), then outer skirts, then (hexagons) 3 diagonal skirts; sample = `sample_dir(frame.sample(sector, s, t))` with `CellFrame::new(cell, n)`, `n` even in 2..=64; triangles per grid cell: `(s,t),(s+1,t),(s,t+1)` and `(s+1,t),(s+1,t+1),(s,t+1)`; `LatticePoint` is an integer barycentric point (canonicalised) and `sample_dir` is exact-op; a coarse border sample equals the even fine sample (ADR-0011). Children of a hex: a centre child (1 parent) and edge children (2 parents, primary = lowest raw); half-cell pieces draw one side of an edge child, cut along a diagonal through its centre, each side lying in one parent.
terrain.rs: `PlanetTerrain::sample(d) -> TerrainSample { height, mask }`, `surface_point(d)`. `uv_of` is `pub(crate)` in mesh.rs.
tests/banned_ops.rs: scans planetary-core src for `.sin(` `.cos(` `.powf(` `HashMap` `Instant` etc; platform-width integers are banned only inside `// BORDER-CRITICAL BEGIN/END` regions and in whole files that are scanned whole (hex/mapping.rs). Put no libm call anywhere in the new files.
