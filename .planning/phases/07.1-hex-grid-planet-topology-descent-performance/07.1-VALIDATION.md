# Phase 7.1 — Validation Strategy

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | cargo test (libtest); no new framework or dependency |
| **Quick run command** | `cargo test -p <crate touched> --locked` (planetary-core, planetary-terrain, planetary-app, engine-render, engine-sdk) |
| **Full suite command** | `cargo fmt --all -- --check && cargo clippy --workspace --all-targets --locked -- -D warnings && cargo test --workspace --locked && cargo run --locked -p xtask -- check-deps && cargo run --locked -p xtask -- check-canary && cargo test --workspace --exclude planetary-core --exclude planetary-terrain --exclude planetary-app --locked` |
| **Cross-target** | `cargo check --workspace --locked --target x86_64-unknown-linux-gnu` and `--target aarch64-apple-darwin` (existing target dirs; no new target dir) |
| **Benchmarks (report only, never asserted)** | `cargo run --locked -p planetary-app --example planetary_flight -- --bench-descent` (debug) and the same with `--release` (single reused `target/release`, only with >= 3 GB free) |
| **Estimated runtime** | quick 20-120 s per crate; full ~6-10 min in debug (descent suites at real defaults dominate) |

## Sampling Rate

- **After every task commit:** `cargo test -p <crate touched> --locked` (plus `--test banned_ops` for any planetary-core src change)
- **After every plan wave:** full suite; cross-target checks after waves that touch crates/ (07.1-03, 07.1-09) and at the end
- **Before `/gsd-verify-work`:** full suite green, then the human window flight (07.1-18 Task 2)
- **Max feedback latency:** 180 s for quick runs

## Wall-clock and determinism rules

- Wall-clock time is read ONLY in `extensions/planetary/planetary-app/src/telemetry.rs` (`WallClock`). The scan `no_wall_clock_in_planetary_crates` in `planetary-app/tests/sdk_only.rs` allowlists exactly that file for the Instant token (new test `wall_clock_only_in_telemetry_module`); all other banned tokens stay banned everywhere. The planetary-core `banned_ops` scan (src only) is unchanged and still forbids wall-clock types in core.
- Tests use `SimClock` (default of `PlanetaryApp::new`) and assert counted values only (ADR-0008 rule); wall-clock numbers appear only in bench output, CSV and SUMMARY/ADR evidence.
- Goldens (`GOLDEN_HEX_DIRS`, `GOLDEN_HEX_MESH`, existing ADR-0008/0010 goldens) are Windows-computed; Linux/macOS confirmation is pending hosted CI, which is blocked by GitHub billing.
