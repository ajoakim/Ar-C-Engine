## Deviations from Plan
1. [Rule 1 - plan constants inert] The planned rock thresholds (`slope` 0.05 to 0.2, with `slope = 1 - n.d`, quadratic in the inclination: 0.05 is about 18 degrees) never occur: measured land slopes are p50 about 1e-5, p99 about 1e-4, max below 2e-4 at levels 4 to 20 (400 seeded patches per level). With them `rock_t` was identically 0 and palette rows 3..7 unreachable. Kept the formula, set `ROCK_SLOPE_LO = 1e-5`, `ROCK_SLOPE_HI = 1e-4`; added `rock_ramp_is_not_inert_on_real_land` (more than 20 % of land vertices past LO, between 0.5 % and 20 % at full rock, level 12). Recorded in ADR-0015. The synthetic "steep vertex q > 0.6" test uses `slope = 2 * HI`.
2. [Rule 1 - colour pop at handover] The ramp depends on the mesh normal, hence on the level. A coincident child vertex's morph target must carry the parent's ramp. Added `uv_at_level` (border stencil of the parent level, mask recomputed with the 3-octave `mask_at`) for hex and cube border cases, and for interior cube vertices the parent's own stencil from the child grid (positions two cells away), so there are no extra samples. A first version that tapped every coincident vertex doubled cube worker time (cube frames-to-detail 75 to 173) and was replaced. Test `cube_v2_morph_target_colour_matches_the_parent_mesh`: 553 of 600 coincident vertices bit-equal to the parent mesh colour, worst row difference 0.016 (a row step is 0.125). Hex uses the border stencil of the parent level (about 4 extra samples per found vertex, no measurable cost) and has no independent colour-continuity test.
3. [Test form] "texture height observable through the create_texture call in a NullBackend setup test": `NullBackend` only exposes a texture count, so palette selection is a pure function `palette_for` with a unit test (rows and bytes for v1, v2, debug).
4. [Test tolerance] v2 `uv.y` is checked against the ramp recomputed from the vertex's f32 normal with tolerance 2e-3 near the rock threshold (f32 normal error moves the slope by up to 2e-7, which is 1.2e-3 of a row over the 9e-5 ramp width) and 2e-5 where `rock_t = 0`. Derivation in the test.
5. [Bench result vs the "no regression beyond 10 %" instruction] v2 costs real time; see Benches. The hex numbers are about 25 percent worse than plan 24 and I did not hide that behind a fix I did not make.
6. `uv_v2` takes the existing `uv` instead of `(terrain, sample, normal, dir)`; the sample is already folded into `uv` (height and mask) at that point.
7. The flag `--no-haze` was not added (the plan defers flags to plan 26); `AppSettings.haze` exists.

## Benches (release, Windows, free-running workers)
`--bench-descent --frames 600`, worst band is `<100 m`, p95, budget 16.7 ms:

| topology | plan 24 (re-measured, v1 params) | v2 (5 hex runs, 2 cube) | result |
|---|---|---|---|
| hex | 11.02 ms (plan 24: 10.8 to 11.7) | 14.78 / 14.23 / 14.26 / 15.42 / 13.73 ms | PASS, headroom now 1.3 to 3 ms |
| cube | 1.41 ms (plan 24: 1.48) | 1.82 / 1.63 ms | PASS |

Stats of the descent run, v1 vs v2 (max nodes visited / max wanted / max drawn / max held in the `<100 m` band): hex 907 / 807 / 334 / 1625 vs 1221 / 900 / 251-255 / 1497-1522; cube 562 / 900 / 258 / 679 vs 730-874 / 900 / 168 / 346. The v2 relief bound is wider, so selection keeps more nodes and hits the 900 wanted cap; cube v2 holds fewer meshes in the same frames because workers are slower. No lag, leaf or node bound in the tests was raised.

`--bench-stream --fast` (frames-to-detail / convergence), plan 24 values and the v1 re-measure agree (hex 167 / 231, cube 76 / 55):

| topology | plan 24 | v2 | change |
|---|---|---|---|
| hex | 167 / 234 | 206 / 290 | +23 % / +24 % |
| cube | 75 / 53 | 80 / 60 | +7 % / +13 % |

This is over the 10 percent allowance on hex (and on cube convergence). Cause measured: the ridge layer adds a 5-octave fbm to every terrain sample (22 to 27 octaves, +23 %), and the hex frames-to-detail with all colour work disabled was 212, i.e. the generator alone. Not fixed here (a faster noise or fewer ridge octaves is a plan 26+ decision); flagged for you.

Window runs (release): `--descent --fast --frames 400` on hex and with `--topology cube` both ran to "engine shut down" cleanly (the shell exit code shown was that of `tail`, the log reached the shutdown line).
