## The reselect reuse: why it is exact

`select_cells` is a pure function of the view, `prev_split`, the held ranges, the fixed configuration and the model. The stored selection is reused only when all of these hold: `always_reselect` off, diagnostics off, no retained ages, a stored selection that was a fixed point of the hysteresis (equal to the `prev_split` it was computed from), no node or leaf budget hit and no trim, an unchanged `held_version` (bumped on every upload batch, destroy and teardown), and `SelectSlack::allows(view_at_selection, view_now)`:
- identical views always pass; otherwise the projection scale is bit-equal, both frustums are present or both absent, the eye is finite and moved by `de <= eye_cap` with `de + 0.05 m < margin_eye`, and the planes changed by `shift + alpha * (d_plane_max + de) + 1e-3 < margin_plane`;
- `margin_eye` is the minimum over EVERY evaluated cell (culled ones included) of the metres of eye translation that could flip a decision: the in-cone test, the horizon test (outside the cone it compares an angle with `a_e + a_1`; the slope of `a_e` is bounded at radius `(r_e + occluder) / 2`, which is why the eye move is capped at `(r_e - occluder) / 2`), and the two screen-space-error thresholds on the clamped distance (exactly 1-Lipschitz; tested). Cosine gaps lower-bound angle gaps. Anything unbounded contributes 0;
- `margin_plane` and `d_plane_max` cover the frustum test per cell (visible: smallest `dist + radius`; culled: the best excluding plane); `alpha` and `shift` come from `View::plane_change`, so near-plane offsets that change with altitude are covered;
- heap pop order can differ under a motion the slack allows, which cannot change the result without a budget hit: the node budget counts the same evaluated cells, and the running piece estimate never decreases (a cube split adds three; an eager hex split removes at most the pieces of its forced group and adds at least their children), so a re-run cannot newly trip `leaf_budget_hit`. This is an argument recorded as a comment at the predicate, not a machine-checked proof; the equality tests check its consequence.

Evidence. `select_slack.rs` (cube and hex, 5 altitudes from 400 km to 12 m, 160 seeded view changes each, translations and rotations at fractions 0.001 to 4000 of the slack): all 417 (cube) and 499 (hex) allowed changes left split, stats and pieces exactly equal; of the refused changes 74 and 82 did alter the selection (teeth). Mutation check: with the margin comparison disabled, 3 of the 7 `reselect_equality.rs` tests fail at the first divergent frame. `reselect_equality.rs`: two apps (reuse and `always_reselect`) on the simulated clock with workers settled each frame and adaptive caps on, compared on EVERY frame for the wanted pieces, wanted levels, drawn set, wanted split and the whole `TerrainReport` except `reselect_skipped` and the `range_lookups` probe counter: scripted descent, fast free-flight and a 600-frame seeded random flight (stationary, 0.2 mm moves, in-place rotations, 90-degree turns, teleports, 3 m per frame moves) on hex and cube plus a second hex seed; 7 tests, all exact. Teleport frames are asserted never reused. Terrain-level tests: no reuse after an upload or destroy, none under a leaf budget hit, same selection as `always_reselect`.

The decision margins cost about 5 percent of a hex selection, so `select_cells_with(.., want_slack)` computes them only when the previous real selection was a fixed point (`TerrainSystem.settled`); a misprediction costs one extra real selection and can never cause a wrong reuse, because a selection stored without margins is never reusable. This was added after one intermediate-build run measured 4.18 ms in `<100 m`.

The margins are small in practice (eye margins 0.02 to 0.5 m at the tested altitudes, a minimum over about 1300 cells), so the reuse is effectively for a still camera and sub-decimetre motion, and only once uploading stops.

## Deviations from Plan

1. [Scope order] `Scope` order follows the code (Select, Closure, Score, Cull, SetBuild, Requests); the plan listed Cull before Score. Mapping: Select = `select_cells` (reuse included); Closure = culled-split retention and piece rebuild; Score = request scores; Cull = diagnostics-only unsplit classification (0 here); SetBuild = `prev_split`, `wanted`, ancestor closure, stale set; Requests = planning and issuing.
2. [Counter] The plan asked `prep_lookups` to count `footprint`, `parents`, `neighbors` and `required_splits` calls through a `CountingTopology` wrapper. A wrapper would change the app's topology types, so `prep_lookups` counts the resident-range probes of `select_cells` (deterministic under `SimClock`, 0 on a reused frame). Call-cost attribution came from a one-off microbenchmark (above), not a permanent wrapper.
3. [Margin shape] `View::orientation_delta` returns the chord `|n_new - n_old|` (the exact Lipschitz constant) instead of `1.5708 * max |n_new - n_old|`; a separate `shift` term covers the plane offset change. No looser than the plan's, and exact.
4. [Cache location] The footprint cache is a per-thread direct-mapped memo in `hex/topology.rs` rather than a per-system object: a per-system cache needs a `Topology` trait or `select_cells` signature change, which the plan says to stop at and record. The memo is bounded (16384 slots a thread, allocated on first use), holds nothing that can go stale (a pure function of the cell id), so it needs no eviction with held meshes (T-07.1-27-02).
5. [Not done] Reusing the `wanted`, `drawn` and scored vectors across frames (candidate (c)) was not done: the profile does not support it (SetBuild is 0.15 ms).
6. [Test scale] The equality paths run on a reduced world (8 cells per edge, max level 10) so the debug suite stays tolerable (about 100 s for `reselect_equality.rs`); the release benches run the real defaults.
7. [Bench output] The bench-stream per-scope table prints one topology per run (the flag selects it); hex and cube are compared in this summary.
8. [Test-only] `PlanetaryApp::set_pose_override` exists so a seeded random flight can drive the camera deterministically.
9. [Cube] The cube pays about 0.08 ms more prepare.
