# Phase 07.1 Plan 27: Hex prepare cost (BEFORE profile, written first)

This file is committed before any optimisation code, so the git history shows the targets and the
BEFORE numbers precede the reductions. The final summary replaces it.

## Targets, stated before the reductions

1. Hex `prepare` p95 below 4 ms in the worst altitude band (read from the `prep_*` columns, not from the bench-descent band table, which is prepare plus gpu_frame).
2. Hex frames-to-detail within 25 percent of cube.
3. If a target is not met, say so and name what remains. No bound, tau, hysteresis, relief bound or adaptive target (8 ms) is loosened to hide cost.

## Environment

Release build, Windows, free-running workers, `--bench-descent --frames 600` and `--bench-stream` (33 ms paced), each configuration run 3 times (every run recorded, not averaged away). Profile hooks: `TerrainSystem::prepare_with(view, &mut dyn ScopeProbe)` with scopes Select, Closure (culled-split retention plus piece rebuild), Score (request scores), Cull (diagnostics only, empty here), SetBuild (prev_split, wanted, ancestor closure, stale set), Requests (planning and issuing). Timing comes only from `Telemetry` (the single clock reader).

Note on baselines: the 07.1-25 SUMMARY reports hex descent p95 13.7 to 15.4 ms. On this session's machine state the unmodified code measures 10.85 / 10.95 / 11.11 ms in the `<100 m` band, which is the plan-24 range (10.8 to 11.7). The machine, not the code, differs; all comparisons below are within this session.

## Top contributors to hex prepare (worst bands, `100 m-1 km` and `<100 m`)

1. `select_cells` is 49 to 57 percent of prepare (avg 4.5 to 4.9 ms of 7.9 to 9.3 ms), cube 0.46 to 0.63 ms.
2. Request scoring is 19 to 23 percent (1.8 to 2.1 ms); cube 0.21 to 0.25 ms.
3. Retention and piece rebuild 10 to 16 percent (0.8 to 1.5 ms); requests 7 percent (0.7 ms); set building 1.5 percent.

Microbenchmark of the topology lookups (release, ns per call, cells along a descent line plus their neighbours): hex footprint 2796, parents 67, children 121, neighbors 119, required_splits 159, primary_parent 62; cube footprint 274, parents 33, children 34, neighbors 110, required_splits 491.

Reading: selection evaluates about 1000 cells per frame and each evaluation calls `Topology::footprint`. The hex footprint rebuilds a `CellFrame` (a ring computation with seven neighbour searches and face finds) and 31 `sample_dir` calls, each allocating in `canonical`, 2.8 microseconds against 0.27 for the cube. About 1000 evaluations is 2.8 ms of the 4.5 ms select time, and the scored pieces call it again. The footprint is a pure function of the cell; nothing else in the lookups comes close.

Budget flags in the descent run (frames below 1 km): hex leaf budget hit in 28 of 312 frames, node budget never, trim never; cube leaf budget 20, trim 20. Uploads happen in every frame below 1 km, so a "no mesh changed" skip cannot fire during the descent; it can only fire in hover.
