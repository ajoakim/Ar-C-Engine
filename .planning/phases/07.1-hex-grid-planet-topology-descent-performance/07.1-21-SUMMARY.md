# Phase 7.1 Plan 21: Generic render path for morph and fog Summary

A planet-agnostic morph vertex layout with a per-draw blend factor and a per-frame distance fog, with offscreen proof that morph 0 and fog density 0 are byte-identical to the previous output. The planetary app still draws PosNormalUv at morph 0 with fog off.

## Commits

- 6f7af23 engine-render: layout, DrawCommand.morph, DistanceFog/fog_factor, extract plumbing, null tests
- e2433cc engine-render-wgpu: vs_morph, uniforms, fog in fs_main, readback identity tests, packet validation
- c50aa16 engine-sdk: create_lit_morph_vertices, SceneState.fog, third pipeline, facade tests

## Uniform sizes changed (the structs grew)

- `FRAME_UNIFORM_BYTES` 48 -> 64 (`fog` at offset 48), `DRAW_UNIFORM_BYTES` 192 -> 208 (`params` at offset 192, still <= stride 256). The `uniform_sizes_and_offsets` test now asserts these numbers; the offsets 64/128/176 are unchanged.
- `FrameUniform::from_light` was replaced by `from_frame(light, fog)` (no shim needed).
- `headless_lit::headless_mixed_scene_uses_two_pipelines`: `pipeline_count` 2 -> 3, because `Runtime::new` now registers the morph pipeline as the plan requires. The assertion is exact and still checks that the two draws use different pipelines.

## Identity-test evidence (offscreen, Intel Arc B580 Vulkan, `cargo test -p engine-render-wgpu -- --ignored`, 10 tests pass)

- `gpu_morph_zero_is_bit_identical_to_pos_normal_uv`: morph pipeline with a different second position/uv at morph 0 equals the PosNormalUv image; an identical second stream equals it at morph 0, 0.25, 0.5, 1.
- `gpu_morph_one_draws_at_second_position_and_uv`: morph 1 equals the PosNormalUv rendering of the shifted quad; morph 1 with a different second uv samples the other texel (red -> green).
- `gpu_fog_density_zero_is_bit_identical`: a fog colour with density 0 changes nothing.
- Before/after: the plain quad image hash is `583ae580ef4842fd` on the pre-plan commit ccd2081 (old shader, run in a temporary worktree) and `583ae580ef4842fd` with the new shader, for the PosNormalUv pipeline, the morph pipeline at morph 0 and fog density 0.
- `gpu_fog_saturates_and_is_monotone_in_distance`: density 1e3 at distance 1 and 1000 give the same colour within 1 LSB (187,137,225 for fog colour 0.5,0.25,0.75); with density 0.2 the red surface moves monotonically toward the fog colour with distance (255,0,0 -> 253,63,108 -> 193,133,219).
- Existing gpu_lit and gpu_smoke assertions unchanged (only literals gained fields) and pass.

## Deviations from Plan

1. [Rule 2] `validate_packet` also validates `packet.fog` (DistanceFog::validate) and rejects a draw whose morph is not in [0,1] (including NaN) with `NonFiniteTransform`, so a hand-built packet cannot bypass the extract checks (threat T-07.1-21-02). Test `null_rejects_bad_fog_and_morph`.
2. Vertex buffer validation (T-07.1-21-01): the null backend (shared `ResourceTable`) rejects a buffer smaller than `vertex_count * stride` (`MeshOutOfBounds`), as for the other layouts; larger buffers are tolerated exactly as before. The plan's wording "not a multiple of 52" is therefore tested as "too short for 52-byte vertices". A layout/pipeline mismatch is also tested.
3. The unlit shader needed no change (its smaller `Draw` struct is valid against the larger bound range; gpu_smoke passes). Morph with the unlit shader is rejected at pipeline creation by `vertex_entry_point`.
4. Both vertex entries output a camera-relative `rel` varying; fog uses the distance to the camera, so it works with morphed positions. Shading uses the vertex normal at every morph value (there is no second normal); ADR-0014 (a later plan) must record this.
5. Files beyond the plan list: `crates/engine-render/src/resources.rs` (packet validation), `crates/engine-sdk/tests/headless_lit.rs` (pipeline count), `crates/engine-sdk/tests/morph_fog.rs` (new). `VertexLayout` is not re-exported by engine-sdk, so the SDK test compares the layout through its Debug name.
