# Phase 07.1 Plan 24: Morph driving Summary

Every drawn piece now gets a geomorph factor from the selector's own refine distance (`m = 1` where the parent was split, `0` at `1.25 x` the cell's own refine distance), refined cells are shown at exactly 1.0 on their first frame, falls are slew-limited to 1/8 per frame, and handover continuity is proven numerically on hex and cube.

## What was built
- `lod::refine_distance(model, proj_scale, tau, level)` and `lod::morph_factor(d, d_start, d_end)` (clamped linear, NaN-free). The selector is not rewritten; tests tie `refine_distance` to `screen_space_error` (cube, level 5) and to `geometric_error * proj_scale / tau` for cube and hex models, levels 1..16, 1e-9 relative.
- `TerrainConfig`: `morph_enabled = true`, `morph_end_scale = 1.25` (valid 1.0..1.9), `morph_frames = 8` (>= 1 when enabled); validated in `TerrainSystem::new`.
- `gpu_frame`: factor per drawn cell (keyed by cell, so hex half variants share it); refine-appearing cells at 1.0, otherwise `max(m_distance, prev - 1/morph_frames)`; level 0 always 0. `TerrainSystem::drawn_morph(cell)` and `PlanetaryApp::drawn_morphs()` expose the shown values.
- `TerrainReport` and telemetry CSV (41 -> 46 columns): `morph_min`, `morph_mean`, `morph_first_frame_defects`, `handover_gap_max`, `multi_level_handovers`.
- ADR-0014 amendment "driving".

## Hex reference numbers (the 81 / 59 question)
The 81 / 59 in plan 24 and 07.1-19 are CUBE numbers: at the 07.1-19 commits (13662b9..801f657) `PlanetaryApp` was hard-wired to `TerrainSystem<CubeSphere>`; hex only became the app default in 07.1-17 (88aee37, which is earlier in plan order but later in git history than 07.1-13 and the 07.1-19 code). So 07.1-19 has no hex baseline. The first hex numbers on record are in 07.1-17 (release, adaptive, 33 ms paced): hex fast 156 frames-to-detail / 216 convergence / 105 uploads/s, hex scripted 197 / 138 / 110, versus cube fast 72 / 49 / 161 and cube scripted 160 / 43 / 173. Plan 23's 165 / 225 (PRE) and 166 / 228 (AFTER) and this plan's 167 / 234 are consistent with that: hex fast has been about 2x cube since the hex topology landed (+7 % frames-to-detail and +8 % convergence from 07.1-17 to now, spread over plans 18-24). It is not a regression introduced in plans 22-24. Not fixed here, as requested.

## Deviations from Plan
1. [Plan wording] "at EVERY refine event the shown morph of the replaced parent is exactly 0.0" holds after the initial stream-in, not during it. While the app first fills in from the roots, a parent is shown at 1.0 on appearing (refine guard) and replaced a few frames later by the next streamed level while it is still slewing (up to 0.875). The slow-approach test therefore starts asserting from the first frame at which drawn == wanted (hex frame 72, cube frame 71) and records the warm-up pairs (hex 56, cube 59); the displacement bound `m_parent * delta <= m_parent * bound` is asserted on all frames including warm-up. After that point there are zero events with a morphing parent on both topologies. The ADR amendment states this limit.
2. [Plan wording] Bound `geometric_error + residual` is evaluated at the grandparent level of the replaced parent (the parent's own vertices against its morph target, which is the grandparent surface); at the parent's own level it is looser. Measured delta stays under 6 % of it.
3. [Rule 1] The system's multi-level counter first counted any replaced ancestor found along the primary-parent chain even when another (hex) parent was directly replaced; found by the independent recomputation in `morph_handover`. It now counts only cells without a directly replaced parent. Commit b718edc.
4. [Not done] The "child `morph_position` equals the parent's own surface to 4 f32 ulps" vertex check of the slow-approach test was not re-derived here: plan 22 proves child morph targets lie on the parent mesh surface (hex 3.7e-9 m, cube 4.0e-9 m worst error) and the slow-approach test shows `m_parent == 0` so no blend with the parent target remains; the f32 allowance (4 eps of the largest offset) is added to the delta in the bound test instead.
5. [Rule 3] `Harness` in `terrain_stream.rs` made generic over the topology to test hex; `PlanetaryApp::drawn_morphs` added (lib.rs was already in the file list).
6. No BEFORE for scripted `--bench-stream` (plan 23 recorded only `--fast`).
