# Phase 07.1 Plan 17: Hex in the app Summary

The planetary app now flies the hex planet by default (`--topology hex`, N = 16, max_level 16, 8192 visits, 900 pieces) with the cube-sphere as `--topology cube` (N = 32). ## What was built

- `PlanetaryApp` holds a private `AnyTerrain { Hex, Cube }`; public accessors are topology-neutral (`drawn_raw`, `drawn_levels`, `wanted_raw`, `wanted_levels`, `piece_level_at`, `wanted_level_at`, `cut_closed`, `drawn_is_partition`, `held_mesh_count`, `stream_budget`, `surface_radius_at`). Invalid hex N gives `SdkError::App` (test). `AppSettings::default()` is hex, `AppSettings::cube_default()` is the oracle. `stream_bench` is topology-neutral.
- Example: `--topology <hex|cube>` (anything else is a usage error, exit 1), `--debug-cells`; benches print the topology. README documents both.
- `tests/app_headless.rs` runs every smoke test for both topologies (10 tests) plus the invalid-N test.
- `tests/descent.rs`: one generic suite, cube tests keep their names, hex tests carry the `hex_` prefix (all nine of the plan list plus `hex_descent_degrades_with_one_start_per_frame`). Shared `OnceLock` runs per topology and path.

`--bench-stream` (release, adaptive, 33 ms paced):

| Run | lag max / p95 | frames-to-detail | convergence after arrival | uploads/s |
|---|---|---|---|---|

Hex streams detail in noticeably slower than the cube: its prepare cost nearly fills the adaptive 8 ms target, so the caps shrink. Not a correctness issue; a tuning item for plan 20.

Windowed smoke (release, `--descent --debug-cells --frames 400`, timeout 150): exit 0, no panic or error text, about 60 fps (16.7 ms avg) on this run.

## Deviations from Plan

1. [Rule 1 - Bug] The per-frame upload COUNT cap was only enforced in adaptive mode; the byte cap alone admitted 5 uploads at frame 0 on hex because pentagon and half-cell payloads are smaller than the estimate. `gpu_frame` now always enforces `uploads_per_frame` (cube behaviour unchanged: its byte cap was exact). In `planetary-terrain/src/system.rs`.
2. [Rule 3] `TerrainSystem::drawn_split()` added so the app can check closure of the drawn cut generically. A first definition (no drawn cell has a drawn ancestor) was wrong for hex, where coarse half pieces legitimately coexist with finer children. Final check: every split cell has its required splits split, every root split or drawn, every drawn cell is a piece cell of the split set. Hex exact coverage stays proven in planetary-core (07.1-14/15/16b).
3. [Test adaptation, not weakened] `descent_degrades_with_one_start_per_frame` for hex: with one start per frame every root needs its own frame, so the first complete cover is asserted within a bound (cube 10 frames as before, hex 16; measured 5 and 11) and the partition, jump <= 1 and non-empty cut must hold on every frame from then on. `production_path_never_blocks`: the original "all 6 faces drawn" gate is replaced by "once the cut is a closed partition it never stops being one".
4. `tests/streaming_lag.rs` was not parameterised; it now runs on the hex default (bounds unchanged, passes). Cube streaming evidence is the plan 19 record plus the `--bench-stream --topology cube` numbers above.
5. The cube suite uses `AppSettings::cube_default()` (N = 32), the old default.
