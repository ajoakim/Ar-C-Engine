## Flaky test: `engine-core engine_lifecycle_frame_stats_spans`

- Full workspace run in this gate: passed (no flake).
- Alone, 15 consecutive runs: 0 failures.
- `cargo test -p engine-core --locked`, 20 consecutive runs: 3 failures (runs 2, 13, 15), each `crates/engine-core/tests/engine_lifecycle.rs:209` `assertion left == right failed, left: None, right: Some(2)` (the `module_update` span count). It is a real, reproducible flake, not a regression.
- Cause: the tracing callsite-interest cache is process-global. Tests in the same binary that tick an engine run on parallel threads; a callsite (`module_update`) first hit by another thread while no subscriber is set can be cached as "never" just as this test installs its thread-local subscriber, so the span is not recorded. `engine_lifecycle_frame_stats_spans` is the only test that asserts on spans.
- Fix (test-only, commit 2824b68, `crates/` touched justified: one test file, no src change): a static `TICK_LOCK` held by the three tests that tick a started engine (`full_run`, `frame_stats_spans`, `frame_history_from_config`). After the fix: 0 failures in 40 consecutive `cargo test -p engine-core` runs (before: 3 of 20). Residual risk: a different test in another binary cannot interfere (separate processes). fmt and clippy for engine-core stayed green.
