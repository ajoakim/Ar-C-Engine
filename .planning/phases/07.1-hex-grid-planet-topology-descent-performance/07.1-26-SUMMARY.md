# Phase 07.1 Plan 26: Present mode setting and window readout Summary

A generic present-mode and frame-latency setting reaches the wgpu surface through the SDK host, startup info and a throttled altitude/speed/level window title make the flight observable, and a real windowed run shows the 31 ms frames are present-bound, not CPU-bound.

## Commits
- c72ecfe feat: present mode setting, pure selection, monitor refresh accessor (task 1)
- baafb6d feat: SDK startup info, window title plumbing, AppConfig.present (task 2)
- feat: window title readout, startup line, `--present-mode` / `--frame-latency` / `--no-haze` flags (task 3)
- docs: ADR-0016 with the measured table, README, docs_policy test (task 3)
- fix: example tests avoid `use super` (the `sdk_only` guard rejects it)

## What was built
- `present.rs`: `PresentModeSetting`, validated `FrameLatency`, `PresentConfig` (default Fifo/2), pure `resolve_present_mode`, string-only `PresentInfo`. `WgpuBackend::new_with` honours it (warn and Fifo on an unsupported mode); `new` and offscreen keep the default.
- `PlatformWindow::monitor_refresh_mhz`.
- SDK: `StartupInfo` and `SceneState.startup/window_title/take_window_title`, `Runtime::set_startup_info/take_window_title`, `AppConfig.present`; the host keeps a window clone, sets startup info before `setup` and applies the title after each successful frame. Re-exports sit in `run.rs` (the facade test forbids `engine_render_wgpu::` in `lib.rs`).
- App: `title.rs` (`format_title`, `should_update_title`, `speed_from_displacement`), `startup_line`, `update_title` (frame-count throttle every 15 frames, no clock); example flags parsed strictly (usage error, exit 1), `--no-haze` wired to `AppSettings.haze`.

## Measured table (real windowed run, release)
Intel Arc B580 (Vulkan), Windows 11, refresh reported 60.000 Hz, supported modes [Immediate, Fifo] (no Mailbox). `--descent --fast --frames 400`, every run exited 0 (the program's own exit code, run directly without a pipe).

| Request | Active | Lat | avg ms | p95 ms | max ms | prepare | gpu_frame | cpu |
|---|---|---|---|---|---|---|---|---|
| fifo | Fifo | 2 | 31.15 | 34.43 | 46.26 | 6.97 | 3.88 | 10.85 |
| fifo repeat | Fifo | 2 | 31.25 | 34.88 | 49.52 | 7.16 | 3.76 | 10.92 |
| fifo | Fifo | 1 | 31.21 | 34.86 | 51.22 | 7.11 | 3.71 | 10.81 |
| mailbox | Fifo (fell back) | 2 | 31.02 | 34.00 | 48.68 | 7.05 | 3.73 | 10.77 |
| auto | Fifo | 2 | 31.12 | 34.06 | 45.74 | 7.06 | 3.78 | 10.84 |
| immediate | Immediate | 2 | 4.63 | 11.48 | 12.95 | 3.01 | 1.06 | 4.07 |

Fifo frames are about 31 ms while CPU work is about 11 ms: roughly 20 ms per frame is the present wait (about two 60 Hz intervals); latency 1 does not change it. Immediate runs the same flight at 4.6 ms average. The cause of the two-interval Fifo cadence was not isolated. Default unchanged (Mailbox unsupported here, so the rule is not met).

## Streaming effect
No streaming or selection code was touched. A headless `--bench-stream --fast` on the release build printed frames-to-detail 212 (plan 25 reported 206; wall-clock paced runs vary) and `drawn == wanted: never` within its default frame bound, so no convergence number was comparable. Plan 27 owns recovery.

## Deviations from Plan
1. [Rule 3 - facade guard] `engine-sdk/tests/facade.rs` forbids `engine_render_wgpu::` in `lib.rs`, so the present types are re-exported from `run.rs` and `lib.rs` re-exports them from `run`.
2. [Rule 1 - guard] The first example test module used `use super::*`, which `sdk_only` rejects; tests call `super::` paths instead.
3. `StartupInfo.present` is `Option<PresentInfo>` (None headless) instead of a default `PresentInfo`.
4. Parser tests cover the two helper functions (`parse_present_mode`, `parse_frame_latency`) the `main` loop calls, not `main` itself. "A headless frame sets the title only on throttle frames" is tested with `Runtime::take_window_title` (frames 0, 15, 30 of 31).
5. `new_offscreen_with` was added so offscreen accepts the config; no GPU-backed test of it (GPU tests are `--ignored` here).
