Copy the template structure into docs/architecture/adr/0006-spatial-index-hash-grid-first.md with title `# ADR-0006: Spatial Index - Uniform Hash Grid First, Benchmark Later`, `- Status: accepted`, `- Date: 2026-11-26`, `- Requirement/Phase: WORLD-05, WS-05 (spatial backend) / Phase 4`.
Sections (all required by template):
- Context: WORLD-05 needs visibility and region queries through a pluggable interface; planetary and conventional scenes differ wildly in scale; no benchmark data yet.
- Decision: (1) engine-owned `SpatialIndex` trait in engine-spatial with insert/update/remove, `query_frustum`, `query_region`, `query_radius` returning `EntityId`s, output cleared then filled sorted ascending and deduplicated; (2) default backend `HashGridIndex`, a uniform hash grid over f64 coordinates in one explicit index `FrameId`, default cell size 64 m, entities spanning more than `max_cells_per_entity` (default 512) cells kept in an always-tested oversize list, queries whose cell range exceeds the number of stored entities fall back to a linear scan; (3) `LinearIndex` brute-force backend kept as the correctness oracle and second implementation; (4) volumes (`Aabb`, `Sphere`, `Frustum`) are f64 and built from `WorldPos` in the index frame (`FrameMismatch` error otherwise); (5) the index frame should not be rebased; if it is, the caller re-issues `update` for every entity with shifted bounds (no automatic tracking); (6) Frustum convention right-handed, +Y up, -Z forward (matches engine-render camera.rs), finite far plane required.
- Alternatives Considered: BVH (better for static, uneven scenes; rebuild cost), rstar R-tree (dependency, f64 support, insert cost), kiddo kd-tree (points, not boxes), octree (depth tuning). Rejected for now because no benchmark evidence; benchmark deferred to Phase 8 decision spike (WS-05). ECS-integrated spatial: out of scope (no ECS).
- Consequences: simple, O(1) updates, deterministic sorted output; poor for very non-uniform density and huge objects (oversize list mitigates); trait has no backend-specific types so a second backend slots in.
- Evidence: Phase 4 oracle tests comparing `HashGridIndex` with `LinearIndex` over pseudo-random entities (crates/engine-spatial/tests/oracle.rs); Phase 8 benchmark spike will add performance evidence and may supersede this ADR.
Append to docs/architecture/adr/README.md table: `| [0006](0006-spatial-index-hash-grid-first.md) | Spatial Index - Uniform Hash Grid First, Benchmark Later | accepted |`.
