- Context: render backends must be replaceable (HLD), wgpu breaks API about every 3 months, headless tests need no GPU, wgpu/winit confinement from ADR-0002/0003.
- Decision (checkable bullets): wgpu 30.0.2 with WGSL shaders, default features, auto-selected native backend; `engine-render` defines `RenderBackend` (create_buffer, destroy_buffer, create_pipeline, resize, size, submit(&FramePacket)) over engine-owned `BufferId`, `PipelineId`, `TextureId`, `MeshHandle`, with built-in shaders/vertex layouts named by engine enums (`ShaderId`, `VertexLayout`); no wgpu type appears in any engine-render signature; `NullBackend` in engine-render records frames and validates handles via a shared `ResourceTable`; window handles cross from engine-platform to engine-render-wgpu only as `Arc<dyn RenderTarget>` (raw-window-handle 0.6 traits), so engine-render-wgpu does not depend on engine-platform; surface creation is a constructor on the concrete `WgpuBackend`, not part of the trait; reverse-Z Depth32Float, clear 0.0, compare Greater, infinite far plane per ADR-0001; the backend is owned by the SDK app loop on the main thread, never registered as an engine `Module`; cargo-deny `multiple-versions` stays `warn`.
- Alternatives Considered: ash (raw Vulkan; unsafe, Vulkan only), vulkano (Vulkan only), Bevy renderer/rend3 (ties to Bevy ECS/app model or low activity), wgpu types directly in engine-render (couples every crate to wgpu's release cadence), engine-render-wgpu depending on engine-platform for the window (allowed by tiers but couples backend to windowing).
